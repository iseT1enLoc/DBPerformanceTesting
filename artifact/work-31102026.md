## 1. Oracle NoSQL — Native Processes on Host

Two Java processes were already running on the host before Docker was involved:

| Process | Port | Command |
|---------|------|---------|
| KVLite storage node | `5000` | `java -jar lib/kvstore.jar kvlite -secure-config disable -root /kvroot -host tienloc22520792 -port 5000` |
| HTTP proxy (NoSQL SDK) | `8090` | `java -jar lib/httpproxy.jar -helperHosts tienloc22520792:5000 -storeName kvstore -httpPort 8090` |

**Key point:** Security is disabled (`-secure-config disable`), so no credentials are needed to connect.

## 3. Docker Compose — Port Conflict Resolution

The `oracle-nosql` Docker service originally tried to bind ports already held by the native processes.

**Resolution:** Re-mapped Docker container ports to non-conflicting host ports. The container is only needed on machines without a native install.

```yaml
oracle-nosql:
  ports:
    - "5100:5000"   # KVLite native (avoids conflict with native on 5000)
    - "8180:8080"   # Proxy       (avoids conflict with native on 8090)
```

## 5. Integration Test Fixes — `ClientRoundTripIT`

### Problem 1 — Test was silently skipped

`@BeforeAll` checked TCP reachability before connecting. The docker-compose did not expose port 5000 or 8090, so on machines without the native install the test was skipped with no data written.

**Fix:** Expose the correct ports in docker-compose (see section 3).

### Problem 2 — Stale rows caused `queryByAmount` size assertion to fail

`writesFromOneClientAreVisibleToTheOther` inserted rows with `customerId = "it-kv-<nanotime>"`. Because `TableSetup` reuses the table across runs, those rows accumulated and caused:

```
Expected size: 100 but was: 101  (then 102 on the next run, etc.)
```

Attempts and why they failed:
- `DELETE … WHERE customerId LIKE 'it-%'` — Oracle NoSQL SQL does not support `LIKE`
- `DELETE … WHERE customerId = 'it-kv-roundtrip'` — worked for new runs but could not remove old nanotime IDs already in the store

**Final fix:** Drop the table at the start of every test run so it is always loaded from scratch:

```java
// In @BeforeAll, before TableSetup.prepare()
String tableToDrop = TableSetup.tableName(sizer.bytes(), data.size());
kv.executeDdl("DROP TABLE IF EXISTS " + tableToDrop);
```

The write test also switched from dynamic (`nanotime`) customer IDs to fixed constants so future cleanup is deterministic if needed:

```java
private static final String KV_WRITE_CID  = "it-kv-roundtrip";
private static final String SDK_WRITE_CID = "it-sdk-roundtrip";
```

### Problem 3 — No visibility into whether connections actually succeeded

Port reachability (`Socket.connect`) only checks TCP — it does not prove the KVStore accepted the connection.

**Fix:** Added explicit connection-verification methods called immediately after each client is created:

```java
// KV native client
store.executeSync("SHOW TABLES");
log.info("[kvclient] Connected to KVStore at localhost:5000 — OK");

// NoSQL SDK / proxy
handle.listTables(new ListTablesRequest()).getTables();
log.info("[sdk] Connected to NoSQL proxy at localhost:8090 — OK ({} table(s) visible)", tables.length);
```

If either call throws, the test aborts with a clear message naming the failing client and endpoint.
